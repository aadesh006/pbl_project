Shadow Analyzer runs untrusted npm packages inside a namespace-scoped sandbox and inspects what they actually do at the kernel boundary — syscalls, sockets, file writes — using eBPF/LSM hooks that can block malicious behavior in real time, not just flag it after the fact.

Inspection pipeline

STAGE 1
Intake
Package pulled into an isolated namespace before any install script runs.
STAGE 2
Sandbox exec
PID namespace scoping via task→nsproxy→pid_ns_for_children keeps the trace to this package only.
STAGE 3
Kernel hook
lsm/socket_connect checks every outbound connection against an IP blocklist map in-kernel.
STAGE 4
Verdict
Blocked calls are stopped at the hook, not just logged — the package never completes the call.

Core components

Socket-connect hook
A working lsm/socket_connect eBPF program backed by an IP blocklist map — outbound connections to known-bad addresses are refused at the kernel boundary.
Namespace scoping
Filtering keyed off task->nsproxy->pid_ns_for_children so the trace only covers the sandboxed package's own PID namespace, not the host.
Latency measurement
Hook overhead measured with bpf_ktime_get_ns() rather than estimated — the 3.2µs figure above is a real number, not a placeholder.
BPF ↔ C++ event bridge
event_t struct alignment corrected between the BPF side and the C++ userspace side so trace events decode cleanly across the boundary.
